# TokuKos Design Context

This project follows a clean, professional, and data-driven aesthetic tailored for property management.

## Design Context

### Users
- **Owners**: Business-focused, managing multiple assets, requiring clarity on finances (KPIs) and operational efficiency.
- **Residents**: Utility-focused, requiring a simple interface for payments and reporting issues.

### Brand Personality
- **3-word personality**: Tech-forward, Distinctive, Confident
- **Emotional goals**: Trust, Efficiency, Clarity.

### Aesthetic Direction
- **Visual Tone**: Modern SaaS, clean, professional, "Enterprise but accessible".
- **Theme**: Light mode (Primary).
- **Design Philosophy**: Bold Professional - distinctive, tech-forward, memorable
- **Core Colors**: 
  - Brand Primary: Bold Professional Blue (`oklch(62% 0.15 250)`) - vibrant, distinctive, tech-forward
  - Hover State: Deep Blue (`oklch(55% 0.15 250)`)
  - Accent: Warm Coral (`oklch(65% 0.14 35)`) - tech-forward contrast
  - Accent Light: Warm Tint (`oklch(92% 0.03 35)`)
  - Neutral Background: Fresh Off-White (`#FAFBFC`)
  - Text Primary: Deep Navy (`#0A1428`) - enhanced contrast
  - Text Secondary: Medium Blue-Gray (`#5A6B7D`)
  - Status: Success Green, Warning Amber, Danger Red.
- **Design Details**:
  - **Typography**: Bold headings (h1-h3 with dramatic scale), semibold labels for hierarchy
  - **Buttons**: Strong shadows, scale effects on hover, increased visual weight
  - **Cards**: Enhanced borders, subtle gradients, elevated shadows on hover
  - **Inputs**: Thicker borders (2px), improved focus states
  - **Accents**: Warm coral accent color for tech-forward contrast
- **Reference Palette**: ColorHunt #3558727aaace9cd5fff7f8f0 (but amplified for boldness)
- **Components**: Rounded corners (`12px`-`20px` for cards), dramatic shadows, high white-space usage.

### Design Principles
1. **Financial Clarity**: Critical numbers (money, invoices) must always be formatted clearly and stand out.
2. **Component Standardisation**: All modals and forms must follow the shared `Modal` and `input-field` patterns.
3. **Data Hierarchy**: Use distinct visual weights (bolding, font sizes) to separate primary actions from secondary data.
